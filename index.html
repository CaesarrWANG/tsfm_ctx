Abstract · 摘要

用背景文本
改进时间序列预测
以结构化情境表征为接口

背景信息（事件、计划、约束、外部输入）往往决定了序列的未来，但时序基础模型读不懂文本，而让大模型直接给出预测，代价高且过程不可检查。我们在文本和预测之间引入一种带形式语义的结构化情境表征：9B 语言模型把文本解析成效应，确定性编译器把效应变成逐步约束和协变量，并可证明地保证真陈述不会让预测变差；以效应为条件的时序模型由真实序列自监督训练，不需要成对的文本–序列数据。

01 / Introduction

文本辅助时间序列预测

“下周一门店装修停业”“下午 2 点到 5 点用电量将是平时的 4 倍”“风扇负载从 05:48 起调到 0.2”：这些信息不在历史数据里，却直接决定了未来。只看历史的模型无论多强，都无法预见它们。

1.1

现有模型真的在利用背景信息吗？

文本辅助预测的前提是“模型确实用上了背景”。最直接的检验，是比较同一个方法给背景和不给背景时的成绩。GIFT-Eval-CTX 的背景都来自真实未来，保证有用，因此最适合做这个检验（相对 MASE，越低越好，1.0 = 季节性朴素预测）。

发现 1 · 端到端模型几乎没用上

把文本和序列放进一个模型联合训练的 TimeBraid，在两个基准上都与只看历史的时序模型持平：GIFT-Eval-CTX 0.773 对 0.78–0.80，Context-is-Key 0.289–0.294 对 0.290。背景信息在模型内部被“稀释”了。

发现 2 · 大模型用上了，但不擅长数值

大模型确实在读背景：Claude 1.109 → 0.781，GPT-5.6 0.953 → 0.565。但它们的数值预测底子差：不给背景时比季节性朴素还差；给了背景，Claude 在中期和长期仍是 1.08 / 1.15。

发现 3 · 时序模型会预测，却读不了背景

Chronos-2 等只看历史就有 0.78–0.80，数值预测能力最强，但没有接收文本或效应的通道。

缺口

没有一种方法能既用上背景，又保住时序基础模型的数值预测能力。会预测的模型读不了背景，读得了背景的模型又预测不好。

1.2

关键观察：背景一旦变成“显式的未来时间效应”，时序模型就能用上

我们做了一个最简单的实验：不训练任何模型，只把 GIFT-Eval-CTX 的背景换算成预测期内逐步的约束（哪几步等于多少、所有步落在什么范围），再套到原版 Chronos-2 的预测上。

由此得到的判断

  • 背景里的信息本身很有价值，时序基础模型的预测能力也足够强。瓶颈在两者之间的接口
  • 只要把背景转化成对齐到预测时间步的显式效应，即使不训练，也能超过端到端模型和大模型直接预测
  • 再训练时序模型去理解这些效应（只给方向、只给形状、外部输入等），提升还会更大

这就是我们提出结构化情境表征的原因：它是文本和时序基础模型之间的接口，把文本中的背景转化为显式的未来时间效应。

1.3

我们的做法：以结构化情境表征为接口

文本里对预测有用的，大多是可以精确表达的效应：某段时间等于多少、不超过多少、上升还是下降、外部输入怎么变。我们把它们定义成一种带形式语义的中间表征，把问题拆成三件各自好做的事：

1.4

贡献

① 结构化情境表征与安全保证

文本和结构化信息编译到同一种带形式语义的中间表示。我们证明：陈述为真时，约束投影不会增加 CRPS；陈述为假时，增加量不超过陈述的偏差。实证检验中违反 0 次。

② 不需要成对数据的训练

从真实序列的未来中提取效应，加入“说了但没发生”的陈述、不同精度的描述和人造外部输入，自监督地训练以效应为条件的预测模型。

③ 小模型、强结果、可溯源

9B + 0.12B 在 GIFT-Eval-CTX 上超过基于 GPT-5.6 的榜单第一（0.476 对 0.497），在 Context-is-Key 上比 TimeBraid 好约 0.14；每个效应都能追溯到原文句子。

02 / Related Work

相关工作与定位

我们的方法处在四条研究线的交汇处：时序基础模型、用语言模型做预测、文本–序列多模态模型，以及把自然语言解析成可执行表示。

时序基础模型

Chronos / Chronos-2、TimesFM、Moirai、Toto 等在大规模序列上预训练，零样本预测能力强。Chronos-2 支持已知的未来协变量，这正是我们把效应注入模型的接口。
区别：我们不改模型结构，而是给它一种从文本得到协变量的方式，并训练它理解这些协变量。

用语言模型做预测

一类工作把数值序列写成文本，让大模型直接续写（如 LLMTime）；另一类把序列表示对齐到冻结的语言模型（如 Time-LLM）。Context-is-Key 上的强基线是前沿大模型的直接提示。
区别：我们不让语言模型生成任何预测数值，只让它解析文本。

文本–序列多模态模型与智能体

TimeBraid 把文本和序列联合建模，依赖大规模成对数据；CAF-7M 等数据集提供成对语料；MoiraiAgent 让前沿大模型调用时序模型作为工具。
区别：预测器完全不需要成对文本；中间表示可检查，且有理论保证；不依赖前沿大模型。

语义解析与程序辅助推理

把自然语言解析成可执行的领域语言、把计算交给程序（如 PAL、Toolformer 一类工作），已被证明能减少语言模型的计算错误。
区别：我们为预测设计了专门的结构化情境表征，并给出了它的语义在 CRPS 下的安全性质。

03 / Method

以结构化情境表征为接口的预测框架

文本前端（Context-is-Key）和结构化前端（GIFT-Eval-CTX）都编译到同一种结构化情境表征，之后的编译、预测、投影完全共用。

3.1

问题定义

给定历史 y1:T 和背景信息 c（文本或结构化效应），预测未来 yT+1:T+H 的分布。我们把映射 c ↦ 预测分解为：

E = Parse(c) # 效应程序（解析器，学习） (Z, 𝒞) = Compile(E, y1:T) # 协变量 Z ∈ ℝH×12，约束 𝒞t = [at, bt] F = pθ(· | y1:T, Z) # 效应条件预测器（学习） F′ = Π𝒞(F) # 安全投影（确定性）

三个组件

  • 解析器：Qwen3.5-9B + LoRA。只做语言理解：判断效应类型，照抄原文中的时间和数值
  • 编译器：确定性程序。时间与数值换算、约束执行、安全投影
  • 效应条件预测器：微调的 Chronos-2。补全文本没说清的部分：只给方向时的幅度、形状、外部输入与目标的关系

GIFT-Eval-CTX 的结构化效应不需要解析器，直接进入编译器。两个基准共用编译器及之后的全部部分。

3.4

编译器与安全投影

预测之后，对已确认的约束做逐步截断：区间约束对每个样本截断，精确值把分布的中位数平移到该值、离散程度不变。设某一步的预测分布为 F，真实值为 y，约束区间为 C = [a, b]。

定理 1 · 真约束不变差

y ∈ C ⇒ CRPS(F′, y) ≤ CRPS(F, y)点预测：|clip(x) − y| ≤ |x − y|

截断只把区间外的累积分布压到 0 或提到 1，而真实值不在那里，所以被积函数逐点不增。

定理 2 · 假约束损失有界

y ∉ C, d = dist(y, C) ⇒ CRPS(F′, y) ≤ CRPS(F, y) + d点预测：误差 ≤ max(原误差, d)

只有 y 与区间之间长度为 d 的一段会变差，每点最多增加 1。

命题 3 · 精确值平移

δ = |v − y| ⇒ CRPS(F′, y) ≤ CRPS(F, y) + 2δ陈述准确（δ = 0）时不增加

中位数使 E|X − c| 最小，再用两次三角不等式即可。

含义：代码层是可证明的“安全层”，损失只可能来自读错，或者文本本身不准确。端到端模型和大模型直接提示都没有这种保证。

3.5

效应条件预测器与自监督训练

模型

  • Chronos-2 全量微调（约 1.2 亿参数）
  • 11 条效应通道 + 1 条外部输入通道，作为已知的未来协变量输入
  • 通道：下界、上界、方向、可信度、全程上下界、趋势模板、季节幅度、反复偏移方向和水平、季节性、外部输入

训练流程（定稿版本 E16）

  • 短窗口（24–48 步）8,000 步
  • + 长窗口（480 / 720 步）与短窗口回放，8,000 步
  • + 外部输入，3,000 步

自监督训练数据（不需要任何文本）

  • GIFT-Eval 预训练集的真实窗口，不含测试数据
  • 用规则从真实未来中提取效应：一半按结构化格式描述，一半按文本格式描述
  • 描述分三档精度：精确值、大致幅度、仅方向
  • 写入大幅度效应；加入“说了但没发生”的陈述和可信度标签
  • 约 30% 的窗口加入由人造外部输入驱动的成分：比例、平方、带延迟的关系，以及与目标无关的输入
3.6

混合方案

  • 有陈述的步：用预测器的输出，再做安全投影

05 / Conclusion

结论

我们提出以结构化情境表征为接口、把文本信息用于时间序列预测的框架：语言模型只负责把文本解析成效应，编译器以可证明安全的方式执行其中的约束，效应条件预测器从历史中补全文本没说清的部分。它不需要成对的文本–序列数据，只用 9B 语言模型加 0.12B 时序模型，就在 GIFT-Eval-CTX 上超过了基于前沿大模型的智能体，在 Context-is-Key 上接近前沿大模型的直接提示，而且每一处修改都能追溯到原文。

局限

“看过测试题”

解析器的若干修正和外部输入的训练模板，是看过 Context-is-Key 的题型后设计的；预测器的版本也是按测试成绩选的。需要一个独立的文本测试集来检验。解析器已在第四轮冻结，已知失败案例：把未来的“停业”读成历史屏蔽，隐含的节假日没有识别，把“日照峰值出现在 11:54”误读为外部输入。

适用范围

需要常识和类比的题（约占 Context-is-Key 权重的 14%）不在方法范围内，例如“新区靠近河流，参照其他区估计救援次数”。前沿大模型的优势主要在这里。

预测器在文本基准上的贡献偏小

在 Context-is-Key 上约 0.01，比在 GIFT-Eval-CTX 上（0.634 → 0.476）小得多：文本中的效应多数带明确数值，编译器直接写入就够了。
